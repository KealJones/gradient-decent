Gradient Decent / layout

Can page layout run a language model?

The same tiny Shakespeare model as the css page, with no arithmetic written anywhere. Every number is the size of a box. Multiplying is aspect-ratio, adding is boxes in a row, subtracting is the space left over, and finding the largest is a grid column. The page's layout engine does the sums because it has to put the boxes somewhere.

Yes. About 35,000 boxes get laid out for every character, and the widths that come out match a plain JavaScript run of the same weights closely enough to pick the same character. In headless Chrome the dot landed on the same character as plain JavaScript 20 times out of 20, with scores within 0.006. It is also the slowest thing in this collection by a long way: about 650 ms a character, some 18,000 times slower than the JavaScript loop, because laying out 35,000 boxes is a lot more work than 21,000 multiplies. The race below measures both on your machine.

How one character gets made

Eight steps. The script builds the boxes once, then only carries widths from one stage to the next and rolls the dice.

  1. CSS
    Embed.

    The last 8 characters become class names. Each class sets lengths: "character 12 at position 3" is nine heights, such as --p27: 412.3px. A negative number goes in a second variable, because a box can't be less than nothing tall.

  2. Layout
    Multiply.

    One box per weight. Its height is an input and its aspect-ratio is the weight, so layout has to make it input × weight wide. Nobody wrote a multiply.

  3. Layout
    Add.

    The boxes for one neuron sit side by side in a flex row. The row is as wide as all of them together, which is the sum. Terms that should count against the neuron go in a second row.

  4. Layout
    Subtract and clamp.

    Under the adding row, the taking-away row is placed in the same width, and a stretchy box gets whatever is left. That is the sum minus the rest. If the taking-away row is longer there is nothing left, and nothing is as low as a width goes, which is exactly ReLU.

  5. JS
    Carry.

    A ResizeObserver reports the 192 leftover widths and the script writes each one back as a height for layer 2. It copies the number; it does no sums.

  6. Layout
    Layer 2, and the dice.

    The same three moves again, one row per character. Each row also gets a fixed box so no score falls below zero, and one random-width box. Adding the right kind of random amount to every score and taking the largest is the same as sampling from the model's odds.

  7. Layout
    Find the largest.

    The observer carries the 37 scores to 37 bars in one grid column. The column is as wide as the longest bar, so that bar is the only one with no room left beside it. A container query on that leftover room gives a dot a size only where the room is zero.

  8. JS
    Write.

    The observer fires again, for the one dot that just appeared. Which dot it was is the character. Append it, change the class names, and wait for the next frame.

Every forward pass happens inside one frame. The observer's callbacks run during layout, each one changes something deeper in the page, and the browser lays out again and calls back again until nothing moves.

JS the carrying

  • Building the 35,000 boxes from the weights, once
  • Characters to class names
  • Copying 192 + 37 widths from one stage to the next
  • Rolling 37 random numbers (this uses Math.log)
  • Appending the character the dot landed on

Layout all of the arithmetic

  • Every multiply (aspect-ratio)
  • Every add (boxes in a flex row)
  • Every subtract and both ReLUs (leftover space)
  • Bias (a box of fixed size)
  • Argmax (a grid column and a container query)

What it says

  • Layout is a calculator if you hold it right. It multiplies, adds, subtracts, clamps and finds a maximum without a single calc(). Run the race for the numbers on your machine.
  • Sizes are fixed-point. Chrome lays out in 64ths of a pixel, so every box is rounded. One unit of the model is 256 pixels in layer 1 and 64 pixels in layer 2, which keeps the rounding well below the gaps between scores.
  • The clamp is free. ReLU usually needs its own step. Here it falls out of the fact that a box can't have negative width, which is the same limit that makes negative numbers awkward everywhere else on this page.
  • The observer is the loop. Nothing polls. A character is finished when the browser has nothing left to resize.

Gotchas found on the way

  • An aspect-ratio of 0 means "no ratio", so a weight of exactly zero has to be left out, not drawn.
  • A ResizeObserver stays silent when a size doesn't change. If the same character wins twice its dot would not report, so the dot is 40 pixels on even steps and 41 on odd ones.
  • Within one frame the observer only reports on elements deeper in the page than the ones it just reported, so the stages have to be nested deeper and deeper in the markup.
  • If a stage really doesn't change, nothing fires. A timer reads the dots directly after 700 ms; the race reports how often that happened.
  • Only tried in Chrome.
