Gradient Decent

Small language models run by the parts of a browser that were built for drawing and styling, not for maths. Canvas blend modes, CSS colours and transforms, the audio engine, and whatever else turns out to be able to multiply.

The name is the joke. Gradient descent is how a model gets trained. Nothing here is trained and nothing descends: these pages only run models, and they do it with actual colours and gradients. So it's gradient, and it's decent.

The experiments

Each page runs a real model, shows the browser feature doing the work, explains it step by step, and races it against a plain JavaScript loop so you can see what the trick costs.

CanvasCan a 2D canvas hold a conversation?

A chat model that talks like a three-year-old and remembers the conversation. The weights are pictures and the multiply is a blend mode.

1.8M weights · about 15 tokens a second CanvasCan blend modes write a story?

A ternary-weight model that writes wobbly children's stories. Every weight is a red, green or black pixel.

1M weights · 20 to 30 tokens a second CSSCan a stylesheet run a language model?

A Shakespeare babbler whose whole forward pass is CSS colour maths: color-mix() sums and relative-colour multiplies.

21K weights · about 31 ms a character CSS, no scriptCan a page with no script write by itself?

The same Shakespeare babbler with the JavaScript taken out. The clock, the memory, the dice and the text are all CSS.

21K weights · a little under one character a second · Chrome and Edge only CSSCan CSS transforms multiply matrices?

The same Shakespeare babbler as a wall of tilting cards. Every neuron is a long list of matrix3d() functions and the answer is how far its card tips.

21K weights · 50 to 90 ms a character AudioCan you listen to a model think?

The same Shakespeare babbler as a Web Audio graph. The weights are a sound file, each layer is a convolution reverb and ReLU is a distortion curve.

The rules

  • The maths has to be done by something that wasn't meant for it. A blend mode, a colour function, a transform, a reverb, a gradient. Not WebGPU, WebGL or WASM, which is how everyone else does it.
  • JavaScript is allowed for the bookkeeping. Every page says exactly which steps are script and which aren't.
  • It has to be a real model and it has to be right. Each one is checked against an ordinary implementation of the same weights, and the page lets you rerun that check.
  • It doesn't have to be fast. It won't be. Each page says how slow.
  • It doesn't have to work everywhere. These lean on the newest corners of the browser, and so far they have only been checked in Chrome. Each page lists what it needs.
